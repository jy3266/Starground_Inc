문제

기술이 부족한 것이 아니라, 데이터의 신뢰가 부족합니다

감축량의 근거가 불명확하고 검증 주체가 분리되어 있어, 데이터는 존재하지만 그 생성 과정·행위의 증거·검증 경로가 하나의 구조로 연결되어 있지 않습니다.

STARGROUND OS는 수집·처리·보증·활용의 역할을 분담한 4개 기술 계층으로 구성됩니다. 감축 데이터는 계층 구조를 따라 자율적으로 생성·검증·증명됩니다.

Action Capture

IoT 센서·Gateway·OCR로 현장의 원시 데이터와 비정형 문서를 수집합니다.

LAYER 02

Data Processor

Δ Engine이 감축량을 자동 산정하고, Carbon Schema로 표준화한 뒤 MRV Object로 객체화합니다.

Data Vault

원본은 오프체인에 암호화 저장하고, 해시값만 온체인에 기록해 무결성과 프라이버시를 동시에 확보합니다.

LAYER 04

User Business Logic

Proof Token 2단계 검증, RAG 기반 AI 리포트, 디지털 트윈 대시보드로 데이터를 가치로 전환합니다.

기술 아키텍처

STARGROUND OS — 4계층 운영체계

각 계층은 감축 데이터의 수집·처리·신뢰 보증·활용이라는 역할적 분담 구조(Role-based Architecture)를 가집니다. 계층을 눌러 내부 엔진을 확인하세요.

Carbon Schema — 감축 데이터의 최소 단위

IoT 센서, ERP, PDF, OCR 등 서로 다른 원천 데이터를 하나의 표준 필드 구조로 정규화합니다. 생성 주체와 단위를 통일시켜 모든 감축 행위가 비교 가능하고 검증 가능한 데이터 단위로 존재하게 합니다.

필드명설명예시
emission_source배출 활동의 종류차량, 보일러, 플라스틱 소각
fuel_type사용된 연료의 유형경유, LNG, 전력
activity_value측정값1,250
unit단위L · kWh · m³
timestamp측정 시점2025-05-01 00:00
source_id데이터 출처IoT_0001 / ERP_0003

MRV Object — 데이터의 신뢰 구조화

모든 감축 데이터는 M(모니터링) → R(보고) → V(검증) 단계를 통해 자동으로 객체화됩니다. 검증은 3단계 알고리즘으로 작동하며, 통과한 객체만 해시 처리되어 블록체인에 기록됩니다.

01 · FORMAT CHECK

형식 검증

Schema 구조와의 일치성을 확인합니다.

02 · LOGIC CHECK

논리 검증

데이터 값의 논리적 일관성을 검증합니다.

03 · SOURCE VALIDATION

출처 검증

인증된 기기·고객사로부터 발생한 데이터인지 확인합니다.

Proof Token온체인 기록 항목

Proof Token에는 해시값, 생성 시각, 블록체인 트랜잭션 ID, 검증자 및 발급자 정보가 포함됩니다. 데이터 자체는 온체인에 저장되지 않고 해시값만 기록되어, 무결성은 보장하면서 프라이버시는 유지됩니다.
